## DEF01 — reservar novamente após cancelar

### Como reproduzir

1. Criar um cidadão de teste e autenticar.
2. Criar um horário isolado, daqui a dez dias, com capacidade 1.
3. Reservar esse horário e conferir que a reserva existe.
4. Cancelar e conferir no banco o estado `cancelled`.
5. Com a mesma conta, tentar reservar novamente o mesmo horário.

**Esperado:** nova reserva confirmada, com o histórico do cancelamento preservado.

**Observado:** `sqlite3.IntegrityError: UNIQUE constraint failed: appointments.user_id, appointments.slot_id`.

**Causa identificada:** a consulta de duplicidade procura apenas reservas `booked`, mas a restrição `UNIQUE(user_id, slot_id)` da tabela também impede uma segunda linha depois do cancelamento. No cliente de teste, a exceção é propagada; uma resposta HTTP 500 em configuração de produção não foi medida nesta execução.

**Situação:** reproduzido, sem correção nesta contribuição. A correção e o tratamento de banco existente estão atribuídos à frente de reservas no quadro da equipe.

## DEF02 — check-in libera capacidade indevidamente

### Como reproduzir

1. Criar um horário isolado para hoje, com capacidade 1.
2. Cidadão A reserva o horário.
3. Recepção confirma a chegada. Conferir a transição para `checked_in`.
4. Cidadão B, em outra sessão autenticada e com CSRF válido, tenta reservar esse horário.
5. Consultar todas as reservas do horário no banco.

**Esperado:** recusa de B, com apenas a reserva `checked_in` de A.

**Observado:** o banco ficou com `['checked_in', 'booked']`, apesar da capacidade 1.

**Causa identificada:** a contagem considera apenas `booked`, deixando de contar quem já fez check-in.

**Situação:** reproduzido na base da `main`, sem correção nesta contribuição. Existe uma contribuição separada de Arthur para capacidade; ela ainda precisa ser integrada e retestada.

## Como executar e interpretar

Na raiz do clone, com Python instalado, use o CMD no Windows:

```bat
python -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements-dev.txt
python -m pytest -v tests/test_protecao_sessao.py
python -m pytest -v tests/test_fila.py tests/test_seguranca.py
python -m pytest -v -rx
```

Na base indicada, o último comando termina com `26 passed, 2 xfailed`. Para ver as falhas sem a classificação de defeito conhecido:

```bat
python -m pytest -v --runxfail tests/test_regressao_reservas.py
```

Esse comando deve retornar falha enquanto DEF01/DEF02 persistirem. As reproduções entram na coleta normal do pytest; não ficam escondidas fora da suíte.

Os marcadores `xfail(strict=True)` são ativados somente depois de conferir as etapas de preparação. DEF01 aceita como falha conhecida apenas `sqlite3.IntegrityError`. DEF02 confere o estado e a mensagem esperados. Depois de cada correção, remover o marcador correspondente e exigir aprovação normal. Se o caso passar enquanto ainda estiver marcado, `XPASS(strict)` faz a suíte falhar, sinalizando que a marcação deve ser revista.

Verificações complementares:

```bat
coverage run --source=app -m pytest -q
coverage report -m
ruff check .
bandit -r app.py
```
